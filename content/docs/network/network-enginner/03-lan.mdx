## 3.3 IEEE 802.3 标准（CSMA/CD）
### 3.3.1 CSMA/CD协议
#### CSMA
* **CSMA（Carrier Sense Multiple Access，载波监听多路访问）**
* 基本原理：发送数据之前，先监听信道上是否有人在发送。若有，说明信道正忙，否则说明信道是空闲的，然后根据==预定的策略==决定：
  * (1) **若信道空闲，是否立即发送**。
  * (2) **若信道忙，是否继续监听**。

#### CSMA 监听算法
**(1) 非坚持型监听算法：后退随机时间**
由于随机时延后退，从而==减少了冲突的概率==。问题是因为后退而使信道闲置一段时间，这使==信道的利用率降低==，而且==增加了发送时延==。

**(2) 1-坚持型监听算法：继续监听，不等待**
有利于抢占信道，减少信道空闲时间。但是，多个站同时都在监听信道时必然会发生冲突。
==冲突概率和利用率都高（双高）==

**(3) P-坚持型监听算法**
若信道空闲，以概率 P 发送，以概率 (1-P) 延迟一个时间单位，P 大小可调整。

#### CD 冲突检测原理
CD（Collision Detection）
* 载波监听只能==减小冲突的概率==，==不能完全避免冲突==。
  * 若帧比较长或两个帧**发生冲突还继续发送**，**会浪费网络带宽**。为改进带宽的利用率，发送站应采取边发边听的冲突检测方法，即：
    * (1) 发送期间同时接收，并把接收的数据与站中存储的数据进行比较。
    * (2) 若比较结果一致，说明没有冲突，重复 (1)。
    * (3) 若比较结果不一致，说明==发生了冲突，立即停止发送==，并发送一个简短的==干扰信号== (Jamming)，使所有站都停止发送。
    * (4) 发送 Jamming 信号后，==等待一段随机长的时间==，重新监听，再试着发送。
  * 对总线型、星型和树型拓扑访问控制协议是 **CSMA/CD** (Carrier Sense Multiple Access/Collision Detection，载波侦听多路访问/冲突检测)。
  * 带冲突检测的监听算法==把浪费带宽的时间减少到检测冲突的时间==。

#### 二进制指数后退算法
* **二进制指数退避算法工作原理如下：**
  * (1) 检测到冲突后，马上停止发送数据，并等待**随机时间**再发送数据。
  * (2) 等待的随机时间 = ==τ * Random[0, 1, ...$2^{k}$ - 1]，==
  * τ 是基本退避时间，可以看作固定值。Random 表示随机函数。
  * ==k = min[重传次数, 10]==，根据公式，如果重传 12 次后，k = min[12, 10] = 10，那么可能等待的时间是 τ * Random[0, 1023]，一共有 1024 种可能。
  * 每次站点等待的时间都是随机数，故==后一次退避时间不一定比前一次长==。重传次数越多，退避窗口（即 Random 取值）越大，从而==降低冲突概率==。
  * 如果连续发生 ==16 次==碰撞后，认为网络繁忙或故障，不再尝试发送。

#### 题目一🌟
采用 CSMA/CD 进行介质访问，两个站点连续冲突 3 次后再次冲突的概率（）
A. 1/2  B. 1/4  C. 1/8  D. 1/16
* 【参考答案】C
本题考查二进制指数退避算法，原理如下：
* (1) 检测到冲突后，马上停止发送数据，并等待随机时间再发送数据。
* (2) 等待的随机时间 = τ * Random[0, 1, ...$2^{k}$ - 1]，其中 Random 表示随机函数。
* 注：τ 是基本退避时间，可以看作固定值，k = min[重传次数, 10]，如果重传 16 次后，还不能正常发送数据，认为网络拥塞，不再尝试。
* 冲突 1 次后，k = min[1, 10] = 1，那么等待时间 τ * Random[0, 1]，有 2 个可选数字。
* 冲突 2 次后，k = min[2, 10] = 2，那么等待时间 τ * Random[0, 1, 2, 3]，有 4 个可选数字。
* 冲突 3 次后，k = min[3, 10] = 3，那么等待时间 τ * Random[0, 1, 2, 3, 4, 5, 6, 7]，有 8 个可选数字。
* 即两个站点连续冲突 3 次后再次冲突的概率是 1/8。
* 也可以得出简化公式：==冲突概率为 1/$2^{n}$==（n 表示已经发生冲突的次数，n ≤ 10）。

#### 最小帧长计算
![以太网中的冲突时间](https://sre.ecarry.uk/attachments/20260820094205.png)

* **能检测到冲突条件：** ==发送时间 ≥ 传送时间 + 确认时间==
  * L/R ≥ 2×d/v，则推出最小帧长公式
* 最小帧长公式：
$$L_{\text{min}} = 2 R \times \frac{d}{v}$$
  * R 为网络数据速率，d 为最大距离，v 为传播速度

#### 题目二🌟
在 CSMA/CD 以太网中，数据速率为 100Mb/s，网段长 2km，信号速率为 200m/μs，则此网络的最小帧长是（ ）比特。
A. 1000  B. 2000  C. 10000  D. 200000

**解析**
**1. 提炼已知条件并统一单位**
* 数据速率：
$$R = 100\text{ Mb/s} = 10^8\text{ b/s}$$
* 最大距离：
$$d = 2\text{ km} = 2000\text{ m}$$
* 信号传播速度：
$$v = 200\text{ m/}\mu\text{s} = 2 \times 10^8\text{ m/s}$$
1. 代入公式计算最小帧长 $L_{min}$
最小帧长计算公式为：
$$L_{\text{min}} = 2R \times \frac{d}{v}$$
代入具体数值：
$$L_{\text{min}} = 2 \times 10^8\text{ b/s} \times \frac{2000\text{ m}}{2 \times 10^8\text{ m/s}}$$
**【正确答案】B**

### 3.3.6 虚拟局域网 VLAN
* **虚拟局域网（Virtual Local Area Network, VLAN）**
  * 根据管理功能、组织机构或应用类型对交换局域网进行分段而形成的==逻辑网络==。
  * 不同 VLAN 通信必须经过三层设备：**路由器、三层交换机、防火墙等**。

- **冲突域和广播域：**
  * (1) ==一个中继器和集线器是一个冲突域==
  * (2) ==网桥/交换机的一个接口为一个冲突域==
  * (3) ==一个 VLAN 为一个广播域，交换机默认所有接口都在 VLAN 1==

#### 冲突域
* 冲突域是指连接在同一共享介质上的所有节点的集合，==冲突域内所有节点竞争同一带宽==，一个节点发出的报文（无论是单播、组播、广播），其余节点都可以收到。
![传统以太网冲突域](https://sre.ecarry.uk/attachments/20260820155552.png)
  * 在传统的以太网中，同一介质上的多个节点共享链路带宽，争用链路的使用权，这样就会发生冲突。
  * 同一介质上的节点越多，冲突发生的概率越大。

![交换机组网冲突域](https://sre.ecarry.uk/attachments/20260820155827.png)

  * 交换机不同的接口发送和接收数据独立，各接口属于不同的冲突域，因此有效地隔离了网络中物理层冲突域，使得通过它互连的主机（或网络）之间不必再担心流量大小对于数据发送冲突的影响。
  * ==集线器在一个冲突域，交换机（Switch）/ 网桥（Bridge）的一个接口是一个冲突域。==

#### 广播域
* 广播报文所能到达的整个访问范围称为二层广播域，简称广播域，==同一广播域内的主机都能收到广播报文。== 

![早期的以太网1个广播域](https://sre.ecarry.uk/attachments/20260820163111.png)
  * 在传统的以太网中，同一介质上的多个节点共享链路，一台设备发出的广播报文，所有设备均会收到。

![交换机组网1个广播域](https://sre.ecarry.uk/attachments/20260820163145.png)
  * 交换机对广播报文会向所有的接口都转发，所以==交换机的所有接口连接的节点属于一个广播域，路由器每个接口是一个广播域。==

#### 交换机 VLAN 的划分🌟🌟🌟
* **静态划分 VLAN：** ==基于交换机端口==
* **动态划分 VLAN：** ==基于 MAC 地址、基于策略、基于网络层协议、基于网络层地址==

#### VLAN 划分配置
1. 🌟静态划分 VLAN：** 手动把交换机的某些接口加入到某个 VLAN，配置如下
```bash
[Huawei] vlan 10 //创建VLAN 10
[Huawei-vlan10] quit //退出
[Huawei] interface GigabitEthernet0/0/1 //进入接口
[Huawei-GigabitEthernet0/0/1] port link-type access //把接口设置成access
[Huawei-GigabitEthernet0/0/1] port default vlan 10 //把接口加入VLAN 10
```
2. 动态划分 VLAN：** 根据 MAC 地址、网络层地址、网络层协议、IP 广播域或管理策略划分。
  * **1) 基于 MAC 地址进行 VLAN 划分配置：**
```bash
[Huawei] vlan 20 //创建VLAN 20
[Huawei-vlan20] mac-vlan mac-address 5489-98FC-5825
//把MAC地址为5489-98FC-5825的终端加入VLAN 20
```
  * **2) 基于策略进行 VLAN 划分配置：**
```bash
[Huawei] vlan 20 //创建VLAN 20
[Huawei-vlan20] policy-vlan mac-address 0-1-1 ip 10.1.1.1 priority 7
//基于策略划分VLAN，把MAC地址为0-1-1，
//IP地址为10.1.1.1的主机划分到VLAN 20中，并配置该VLAN的802.1p优先级是7
```

#### VLAN 作用
* **(1) 控制网络流量。** 一个 VLAN 内部的通信（包括广播通信）不会转发到其他 VLAN 中去（==一个VLAN就是一个广播域==），从而有助于控制广播风暴，==减小冲突域，提高网络带宽的利用率==。
* **(2) 提高网络的安全性。** 可以通过配置 VLAN 之间的路由来提供广播过滤、安全和流量控制等功能。不同 VLAN 之间的通信受到限制，==提高了企业网络的安全性==。
* **(3) 灵活的网络管理。** VLAN 机制使得工作组可以==突破地理位置的限制而根据管理功能来划分==。如果根据 MAC 地址划分 VLAN，用户可以在任何地方接入交换网络，实现移动办公。

#### 802.1q 标签🌟🌟🌟
* **802.1Q 标签字段，重点掌握 PRI 和 VID。**
  * **PRI（3位）：** Priority 表示优先级，提供 0~7 共 8 个优先级，当有多个帧等待发送时，按优先级顺序发送数据包。
  * **VID（12位）：** 即 VLAN 标识符，最多可以表示 $2^{12}$ = 4096 个 VLAN，其中 VID 0 用于识别优先级，VID 4095 保留未用，所以==最多可配置 4094 个 VLAN==。==默认管理 VLAN 是 1，不能删除。==
  * ==交换机添加和删除 VLAN 标签的过程由专用硬件自动实现，处理速度很快，不会引入太大的延迟。==
  * 从用户角度看，数据源产生标准的以太帧，目标接收的也是标准的以太帧，==VLAN 标记对用户是透明的。==

#### 交换机端口类型

### 3.4.2 生成树协议 STP
#### STP 基本概念
![STP](https://sre.ecarry.uk/attachments/20260820212548.png)
1. 采用生成树（Spanning-tree）技术，能够在网络中存在二层环路时，通过==逻辑阻塞==（Block）特定端口，从而==打破环路==
![网络故障下的STP](https://sre.ecarry.uk/attachments/20260820213725.png)
1. 在网络出现拓扑变更时及时收敛, ==保障网络的冗余性==

#### 网桥 ID(Bridge ID)
* 桥 ID 一共 8 个字节，由 ==2 个字节优先级和 6 个字节==的 MAC 地址构成。
  * 桥优先级默认为 ==32768==，可以手工修改。最小位**0**, 次级为**4096**(为4096倍数)
  * MAC 地址为交换机背板 MAC。

![网桥ID](https://sre.ecarry.uk/attachments/20260820214126.png)

#### 路经开销 (Path Cost)
* 路径开销是一个端口量，是 STP/RSTP 协议用于选择链路的参考值。
* 端口路径开销的默认值及取值范围由选定的路径开销算法决定，==路径开销与端口带宽成反比==。
* 华为设备路径开销标准有：802.1d-1998、802.1t 及私有的 legacy，**默认为 802.1t 标准**。

| 带宽      | 802.1t   | 802.1d 🌟 |
| --------- | -------- | -------- |
| **10M**   | 2000,000 | 100      |
| **100M**  | 200,000  | 19       |
| **1000M** | 20,000   | 4        |
| **10G**   | 2000     | 2        |

#### STP 选举操作
1. 确定一个根桥 (Root Bridge) 【==选优先级和MAC地址最小的网桥==】
2. 确定其他网桥的根端口 (Root Port) 【==非根桥的端口到根桥最近的端口==】
3. 每个段选择一个指定端口 (Designated Port)【==先选指定桥，指定桥上为指定端口==】
4. 选出非指定端口 (NonDesignated Port)

![STP 选举](https://sre.ecarry.uk/attachments/20260820214934.png)
#### STP 案例分析一
![案例分析](https://sre.ecarry.uk/attachments/20260820225928.png)
哪个端口会被阻塞(block)掉?
**第一步：选举根桥（Root Bridge）**
* **比较原则：** 优先比较==桥优先级==，相同时比较 ==MAC 地址==，值越小越优。
* **计算过程：** 三台交换机的优先级(Pri)均为 `32768`。比较 MAC 地址：`SW1 (0C00.1111.1111) < SW2 (0C00.2222.2222) < SW3 (0C00.3333.3333)`。
* **结论：** **SW1 成为根桥。**
**第二步：选举根端口（Root Port, RP）**
* **比较原则：** 非根桥上到根桥“累计路径开销（RPC）”最小的端口。开销相同时依次比较对端 BID、对端 PID。
* **计算过程：**
  * **SW2：** 端口 1 直连 SW1（开销为 100M 链路的 Cost）；端口 2 经 SW3 到 SW1（开销更高）。故 **SW2 的 1 号端口为 RP**。
  * **SW3：** 端口 1 直连 SW1（开销为 100M 链路的 Cost）；端口 2 经 SW2 到 SW1（开销更高）。故 **SW3 的 1 号端口为 RP**。
**第三步：选举指定端口（Designated Port, DP）**
* **比较原则：** 每个网段（冲突域）选举一个指定端口。根桥上的所有端口均为 DP；非根桥链路依次比较“根路径开销 -> 本地桥 ID -> 本地端口 ID”。
* **计算过程：**
  * **SW1-SW2 链路：** **SW1 的 1 号端口为 DP**（根桥端口）。
  * **SW1-SW3 链路：** **SW1 的 2 号端口为 DP**（根桥端口）。
  * **SW2-SW3 链路：** SW2 和 SW3 到根桥 SW1 的累计路径开销相同（均为 100M 链路开销）。继续比较两者的桥 ID：`SW2 的 BID (32768: 0C00.2222.2222) < SW3 的 BID (32768: 0C00.3333.3333)`，故 SW2 为该链路的指定桥。**SW2 的 2 号端口为 DP**。
**第四步：确定阻塞端口（Alternate Port / NonDesignated Port, AP/NDP）**
* **结论：** 既不是根端口也不是指定端口的端口会被阻塞。**SW3 的 2 号端口为非指定端口，将被逻辑阻塞（Block）。**

#### STP 案例分析二
![STP](https://sre.ecarry.uk/attachments/20260820232058.png)

以下是基于四台交换机拓扑（SW1、SW2、SW3、SW4）的 STP 生成树计算全过程解析（假设各链路速率相同）：
**第一步：选举根桥（Root Bridge）**
* **比较原则：** 优先比较桥优先级，相同时比较 MAC 地址，数值最小者获胜。
* **计算过程：** 四台交换机的优先级均为 `32768`。比较 MAC 地址：`SW1 (0C00.1111.1111)` 最小。
* **结论：** **SW1 成为根桥。**
**第二步：选举根端口（Root Port, RP）**
* **比较原则：** 非根桥上到根桥“累计路径开销（RPC）”最小的端口。开销相同时，依次比较对端 BID、对端 PID、本地 PID。
* **计算过程：**
* **SW2：** 端口 1 直连 SW1（开销为 1 跳）；端口 2 需绕行 SW4-SW3 到 SW1（开销更大）。故 **SW2 的 1 号端口为 RP**。
* **SW3：** 端口 1 直连 SW1（开销为 1 跳）；端口 2 需绕行 SW4-SW2 到 SW1（开销更大）。故 **SW3 的 1 号端口为 RP**。
* **SW4：**
* 经过 SW2 到达 SW1 的路径开销与经过 SW3 到达 SW1 的路径开销相同（均为 2 跳）。
* 比较对端 BID：SW2 的 BID `(32768: 0C00.2222.2222)` 小于 SW3 的 BID `(32768: 0C00.3333.3333)`。
* 故 **SW4 的 1 号端口（连接 SW2）为 RP**。
**第三步：选举指定端口（Designated Port, DP）**
* **比较原则：** 每个网段（链路）选举一个指定端口。根桥所有端口均为 DP；非根桥链路依次比较“根路径开销 -> 本地桥 ID -> 本地端口 ID”。
* **计算过程：**
* **SW1-SW2 链路：** **SW1 的 1 号端口为 DP**（根桥端口）。
* **SW1-SW3 链路：** **SW1 的 2 号端口为 DP**（根桥端口）。
* **SW2-SW4 链路：** SW2 到根桥开销为 1 跳，SW4 到根桥开销为 2 跳，SW2 开销更小，故 **SW2 的 2 号端口为 DP**。
* **SW3-SW4 链路：** SW3 到根桥开销为 1 跳，SW4 到根桥开销为 2 跳，SW3 开销更小，故 **SW3 的 2 号端口为 DP**。
**第四步：确定阻塞端口（Alternate Port / NonDesignated Port, AP/NDP）**
* **结论：** 既不是根端口也不是指定端口的端口会被逻辑阻塞。
* **最终结果：** **SW4 的 2 号端口（连接 SW3）为非指定端口，将被逻辑阻塞（Block）。**

#### 几种生成树协议⭐️⭐️⭐️
* 生成树协议：802.1d⭐️ STP（==慢，拓扑收敛需要 30-50s==）
* 快速生成树协议：802.1w⭐️ RSTP（==快，6s 内完成收敛==）==快速收敛==
* 多生成树协议：802.1s⭐️ MSTP（==实现多个 VLAN 负载均衡==）

* RSTP实现快速收敛的机制（RSTP对STP的改进）：
  * ==(1) 通过端口角色的增补，简化了生成树协议的理解及部署；（替代接口迅速取代失效的根端口）==
  * (2) ==STP端口状态: Forwarding、Learning、Listening、Blocking、Disabled== RSTP简化后:**Forwarding、Learning、Discarding**
  * (3) 配置 BPDU 格式的改变，充分利用了 STP 协议报文中的 Flag 字段，明确了端口角色；
  * (4) 配置 BPDU 的处理发生变化；
  * (5) ==使用 P/A 机制实现快速收敛==； 有点类似触发更新 Push（主动推送）/ Accept（被动接受）
  * (6) 增加保护功能。

#### BPDU
网桥协议数据单元（Bridge Protocol Data Unit）是生成树协议（STP/RSTP/MSTP）中交换机之间互相交流、传递控制信息的**专用数据包**。

简单来说，BPDU 就是交换机之间的“沟通语言”。交换机通过定期互相发送 BPDU，来了解整个网络的拓扑结构，从而计算出谁是根桥、哪些端口该转发数据、哪些端口该被阻塞。

- **BPDU 的主要作用**
  * **选举根桥（Root Bridge）：** 交换机通过比较 BPDU 中的“桥 ID”（BID）来选出网络中最优的交换机作为根桥。
  * **计算最优路径：** 确定各个非根桥到根桥的最短路径开销（Cost）。
  * **阻塞环路端口：** 确定各个端口的角色（RP、DP、AP），并将冗余端口逻辑阻塞，防止生成广播风暴。
  * **感知拓扑变更：** 当网络中的链路或设备出现故障时，通过发送 TCN BPDU（拓扑变更通知）快速触发网络重新收敛。

- **BPDU 的两种主要类型（以标准 STP 为例）**
  * **配置 BPDU（Configuration BPDU）：**
  * **作用：** 用于 STP 的计算和维持拓扑结构。
  * **发送机制：** 网络收敛后，由根桥按固定周期（==默认 2 秒==）发给其他交换机，逐级向全网泛洪。
  
  * **拓扑变更通知 BPDU（TCN BPDU）：**
  * **作用：** 当网络拓扑发生变化（如链路断开或新链路加入）时使用。
  * **发送机制：** 由感知到拓扑变化的交换机主动向根桥方向发送，用来通知整个网络更新 MAC 地址表。

**BPDU 核心包含的关键字段**
在前面做 STP 选举题时用到的字段，本质上全都在 BPDU 里面：

| 字段名称                        | 作用                                                    |
| ------------------------------- | ------------------------------------------------------- |
| **Root ID（根桥 ID）**          | 标识当前网络中被认可的根桥的 BID。                      |
| **RPC（根路径开销）**           | 发送该 BPDU 的交换机到达根桥的总开销。                  |
| **Sender BID（发送者桥 ID）**   | 发送该 BPDU 的交换机的 BID（优先级 + MAC）。            |
| **Sender PID（发送者端口 ID）** | 发送该 BPDU 的交换机接口的 PID（端口优先级 + 端口号）。 |

#### 租期更新
![租期更新](https://sre.ecarry.uk/attachments/20260910165113.png)

* 当客户机的租约期到==50%==，会向DHCP服务器发送==DHCP REQUEST==消息包。
* 如果客户机接收到该服务器回应的==DHCP ACK==消息包，客户机就根据包中所提供的新的租期以及其它已经更新的TCP/IP参数，更新自己的配置，IP租用更新完成。
* 如果没有收到该服务器的回复，则客户机继续使用现有的IP地址，因为租期还剩50%。
* 如果在租期过去50%的时候没有更新，则客户机将在租期过去==87.5%==的时候再次向为其提供IP的DHCP服务器联系。
* 如果还不成功，到租约的 ==100%== 时候，客户机必须放弃这个IP地址，发送==DHCP DISCOVER==重新申请地址。
* 如果此时无DHCP可用，客户机会使用==169.254.0.0/16==中随机的一个地址，并且每隔5分钟再进行尝试。

#### DHCP中继（DHCP Relay）⭐️⭐️
* 随着网络规模的不断扩大，网络设备不断增多，企业内不同的用户可能分布在不同的网段，一台DHCP服务器在正常情况下无法满足多个网段的地址分配需求。如果还需要通过DHCP服务器分配IP地址，则需要跨网段发送DHCP报文。
* DHCP Relay即DHCP中继，它是为解决DHCP服务器和DHCP客户端不在同一个广播域而提出的，提供了对DHCP广播报文的中继转发功能，能够把DHCP客户端的广播报文“透明地”传送到其它广播域的DHCP服务器上，同样也能够把DHCP服务器端的应答报文“透明地”传送到其它广播域的DHCP客户端。

![DHCP Relay](https://sre.ecarry.uk/attachments/20260910170619.png)

##### 工作原理
![DHCP Relay工作原理](https://sre.ecarry.uk/attachments/20260910171342.png)
有中继场景时DHCP客户端首次接入网络的工作原理：
* **1. 发现阶段**：DHCP中继接收到DHCP客户端**广播**发送的 **DHCP DISCOVER** 报文后，通过路由转发将DHCP报文**单播**发送到DHCP服务器或下一跳中继。
* **2. 提供阶段**：DHCP服务器根据DHCP DISCOVER报文中的 Giaddr 字段选择地址池为客户端分配相关网络参数，DHCP中继收到DHCP OFFER报文后，以**单播**或**广播**方式发送给DHCP Client。
* **3. 选择阶段**：中继接收到来自客户端的DHCP REQUEST报文的处理过程同“发现阶段”。
* **4. 确认阶段**：中继接收到来自服务器的DHCP ACK报文的处理过程同“提供阶段”。

#### DHCP Snooping
**DHCP Snooping（DHCP 监听）** 是一种二层网络安全技术，主要用于防御针对 DHCP 的网络攻击，并保障局域网内 IP 地址分配的安全性。
**核心概念**
* **信任端口（Trusted Port）**：连接合法 DHCP 服务器或上行交换机的端口。**允许**接收 DHCP 回应报文（如 `DHCP Offer`、`DHCP ACK`）。
* **非信任端口（Untrusted Port）**：通常连接终端用户的端口。**拒绝**接收来自该端口的 `DHCP Offer` / `DHCP ACK` 报文，防止伪造的 DHCP 服务器接入。

**主要作用**
* **防范伪造 DHCP 服务器（Rogue DHCP Server）**：拦截非信任端口收到的 DHCP 服务响应，确保用户只从合法服务器获取 IP 和网关。
* **建立绑定表（Snooping Binding Table）**：自动监听并记录合法客户端的 `MAC 地址` + `IP 地址` + `VLAN` + `端口` + `租期`。该表是后续防御 IP/MAC 欺骗的基础。
* **配合其它安全机制联动**：
* **DAI（动态 ARP 检查）**：利用绑定表拦截非法 ARP 报文，防御 ARP 欺骗/中间人攻击。
* **IP Source Guard（IP 源防刷/源地址检查）**：校验接口入方向报文的 IP/MAC，防止伪造 IP 盗用网络。

**常见配置命令（以华为交换机为例）**
* 开启全局 DHCP Snooping：
`[HW] dhcp snooping enable`
* 对应 VLAN 开启 Snooping：
`[HW-vlan10] dhcp snooping enable`
* 设置信任接口（连接合法 DHCP 服务器的接口）：
`[HW-GigabitEthernet0/0/1] dhcp snooping trusted`

## 3.7 DNS
* DNS作用：把域名转换成IP地址。
* DNS/DHCP服务器必须为==静态IP地址==，而Web/FTP均可为动态IP。
* Linux系统中提供DNS服务的组件为 ==bind==，主配置文件为==named.conf==。
* 诊断域名系统基础结构的信息和查看DNS服务器的IP地址命令是：==nslookup==。

#### 查询方式
DNS 查询在软考中是必考的基础协议机制，主要通过**主机/客户端发起的请求类型**与**服务器的响应行为**来区分。
**两种查询方式的核心区别**：
| 特性                 | 递归查询（Recursive Query）                          | 迭代查询（Iterative Query）                                  |
| -------------------- | ---------------------------------------------------- | ------------------------------------------------------------ |
| **对被查询方的要求** | 必须给出**最终答案**（成功解析的 IP 或“无此域名”）   | 给出**最佳已知线索**（推荐下一台 DNS 服务器）                |
| **查询责任方**       | 由**收到请求的 DNS 服务器**代劳逐级追问              | 由**发起查询的客户端/服务器**自己逐级追问                    |
| **常见使用场景**     | **终端客户端 $\rightarrow$ 本地 DNS 服务器（LDNS）** | **本地 DNS 服务器（LDNS） $\rightarrow$ 根/顶级/权威服务器** |

![递归和迭代](https://sre.ecarry.uk/attachments/20260910223738.png)
**完整查询工作流程（以客户端访问 `[www.test.com](https://www.test.com)` 为例）**
在一个典型的完整解析过程中，通常是“先递归，后迭代”相结合：
* **阶段 1：递归查询阶段（客户端 $\rightarrow$ 本地 DNS 服务器）**
  * **第一步**：客户端（PC）检查本地缓存与 `hosts` 文件，若无记录，向配置的**本地 DNS 服务器（LDNS）**发送**递归查询**请求。
  * **第二步**：LDNS 接收请求，承接“必须查出最终结果”的责任。
* **阶段 2：迭代查询阶段（本地 DNS 服务器 $\rightarrow$ 各级公网 DNS 服务器）**
  * **第三步（问根域）**：LDNS 查询本地缓存，无结果则向**根域名服务器（.）**发送**迭代查询**请求。根服务器回应：“我不知道 `[www.test.com](https://www.test.com)` 的 IP，但你可以去问 `.com` 顶级域服务器，它的 IP 是 X”。
  * **第四步（问顶级域）**：LDNS 转向 **`.com` 顶级域名服务器**发送迭代查询。`.com` 服务器回应：“你可以去问负责 `test.com` 的权威服务器，它的 IP 是 Y”。
  * **第五步（问权威域）**：LDNS 转向 **`test.com` 权威域名服务器**发送迭代查询。权威服务器查表后，直接返回 `[www.test.com](https://www.test.com)` 对应的 IP（如 `1.1.1.1`）。
* **阶段 3：结果返回**
  * **第六步**：LDNS 将最终得到的 IP 地址缓存到本地，同时回复给客户端 PC，完成整个域名解析。

* **端口与协议**：DNS 查询默认使用 **UDP 53** 端口；主从服务器区域传送（Zone Transfer）使用 **TCP 53** 端口。
* **递归 vs 迭代口诀**：
  * **递归**：**“一查到底”**，要么给 IP，要么报错。
  * **迭代**：**“指点迷津”**，给不出 IP 就提供下一台服务器的线索。
